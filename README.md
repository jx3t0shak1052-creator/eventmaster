# 飲み会管理アプリ 🍻

飲み会の **日時・会場・参加者名簿・参加費の支払い有無** をまとめて管理する Web アプリです。
Node.js + Express の軽量な構成で、外部データベース不要。データはローカルの JSON ファイルに保存されます。

## 主な機能

- **飲み会（イベント）管理**：名前・日付・時間・会場・参加費（1人あたり）・メモを作成／編集／削除
- **参加者名簿**：参加者の追加・削除、区分（幹事・OB など）やメモの記録
- **参加者ごとの参加費**：既定の参加費に加えて、参加者1人ずつ個別の参加費（例：幹事は多め、学生は割引）を設定可能。
  未入力の参加者にはイベントの既定参加費が自動適用され、集計（予定額・集金済み）は個別費を反映して計算されます
- **参加費の支払い管理**：各参加者の支払い済み／未払いをワンクリックで切替、「全員支払済／全員未払い」の一括操作
- **集計ダッシュボード**：参加者数・支払済・未払い・集金済み金額・予定額・集金率をリアルタイム表示
- **検索**：飲み会名・会場での絞り込み
- **エクスポート**：全データを JSON でダウンロード

## セットアップ

```bash
npm install
npm start        # http://localhost:3000
```

開発時も同じコマンドで起動できます（`npm run dev`）。

## テスト

```bash
npm test
```

外部テストフレームワーク不要の簡易 API テストが実行されます（一時データディレクトリを使用し、既存データには影響しません）。

## ディレクトリ構成

```
site/
  index.html    画面の雛形
  app.js        フロントエンド（依存なし・バニラJS）
  local-api.js  サーバーが無い静的配信向けの localStorage フォールバック
  styles.css    スタイル
src/
  server.js   API サーバー（Express）とルーティング・バリデーション
  store.js    JSON ファイル永続化（アトミック書き込み・直列化・破損時退避）
test/
  api.test.js 簡易 API テスト
data/
  db.json     データ本体（自動生成・Git 管理外）
wrangler.jsonc  マネージド Cloudflare ホスティング用の設定（site/ を静的アセットとして配信）
```

### 2つの動作モード

アプリは起動時に `/api/health` を確認し、自動でモードを切り替えます。

- **サーバーモード**：Express サーバーが動いている場合。データは `data/db.json` に保存。
- **ローカルモード**：サーバーが無い静的配信の場合。`local-api.js` が `fetch` を差し替え、
  データをブラウザの `localStorage` に保存。サーバー無しでも全機能が動作します。

## API 一覧

| メソッド | パス | 説明 |
| --- | --- | --- |
| GET | `/api/events` | 飲み会一覧（`?q=` で検索、新しい順） |
| POST | `/api/events` | 飲み会を作成 |
| GET | `/api/events/:id` | 飲み会の詳細（参加者・集計付き） |
| PUT | `/api/events/:id` | 飲み会を更新 |
| DELETE | `/api/events/:id` | 飲み会を削除（参加者も削除） |
| GET | `/api/events/:id/participants` | 参加者一覧 |
| POST | `/api/events/:id/participants` | 参加者を追加（`fee` で個別参加費も指定可） |
| PUT | `/api/participants/:id` | 参加者を更新（部分更新可：`{ "paid": true }` / `{ "fee": 8000 }` / `{ "fee": null }`） |
| DELETE | `/api/participants/:id` | 参加者を削除 |
| GET | `/api/events/:id/summary` | 集計（人数・支払い・金額・未払い者名） |
| GET | `/api/export` | 全データを JSON でエクスポート |
| GET | `/api/health` | ヘルスチェック |

### データモデル

```jsonc
{
  "events": [
    {
      "id": 1, "name": "歓迎会", "date": "2026-09-20", "time": "19:00",
      "venue": "居酒屋 太郎 新宿店", "fee": 5000, "note": "新入社員歓迎",
      "createdAt": "...", "updatedAt": "..."
    }
  ],
  "participants": [
    { "id": 1, "eventId": 1, "name": "田中", "group": "幹事", "paid": true,
      "memo": "", "fee": 8000, "createdAt": "...", "updatedAt": "..." }
  ],
  "meta": { "nextEventId": 2, "nextParticipantId": 2 }
}
```

`participants[].fee` は **個別参加費**。`null`（未設定）の場合はイベントの `fee` が適用されます。
API が返す各参加者の `amount` フィールドが、実際に適用される金額です。

## 設計上のポイント

- **永続化**：書き込みは一時ファイル + rename によるアトミック更新、かつ直列化して競合を防止。破損時は退避して初期化。
- **入力バリデーション**：サーバー側で厳密に検証（日付 `YYYY-MM-DD`、時刻 `HH:MM`、参加費は 0 以上など）。
- **部分更新**：支払いトグル・個別参加費などは該当フィールドのみ送信でき、他のフィールドは保持されます。
- **XSS 対策**：描画時に HTML エスケープを実施。
